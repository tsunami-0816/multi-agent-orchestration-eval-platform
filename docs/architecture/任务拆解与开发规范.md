## 四、开发规范

### 4.1 代码规范

#### 4.1.1 语言与版本

- **Python 版本**：3.12（开发），兼容 3.10 / 3.11 / 3.12（CI 矩阵）
- **编码**：UTF-8，文件头不声明编码
- **行宽**：最大 100 字符（Ruff `line-length=100`）
- **缩进**：4 空格，禁止 Tab

#### 4.1.2 Lint 与 Format

使用 **Ruff 0.6.x** 统一 lint + format，配置在 `pyproject.toml`：

```toml
[tool.ruff]
line-length = 100
target-version = "py310"

[tool.ruff.lint]
select = ["E", "F", "I", "N", "UP", "B", "SIM", "RUF"]
ignore = ["E501"]  # 行宽由 formatter 控制

[tool.ruff.format]
quote-style = "double"
indent-style = "space"
```

**强制要求**：
- 提交前必须运行 `ruff check --fix` 和 `ruff format`
- CI 中 `ruff check` 不通过则合并被阻止
- Import 排序：标准库 → 第三方库 → 本地模块，空行分隔（Ruff I 规则）

#### 4.1.3 类型检查

使用 **mypy 1.11.x** 静态类型检查：

```toml
[tool.mypy]
python_version = "3.10"
warn_return_any = true
warn_unused_configs = true
disallow_untyped_defs = true
disallow_incomplete_defs = true
```

**强制要求**：
- 所有函数必须有完整类型注解（参数 + 返回值）
- `TypedDict` / `Pydantic BaseModel` 用于结构化数据
- 禁止使用 `Any`（除非与第三方库交互且无法避免，需注释说明）
- CI 中 mypy 不通过则合并被阻止

#### 4.1.4 异步编程规范

- **全部 IO 操作使用 async/await**：DB（SQLAlchemy async）、HTTP（httpx.AsyncClient）、LLM（agenerate）
- **禁止在异步函数中调用同步 IO**（如 `requests.get`、`time.sleep`），使用 `asyncio.to_thread` 包裹不可避免的同步调用
- **Celery 任务**：任务函数为同步函数，内部通过 `asyncio.run()` 调用异步逻辑（Celery 5.x 对 async 支持有限）
- **禁止裸 `except:`**：必须捕获具体异常类型，`except Exception` 需记录日志并重新抛出或转换为 AppException

#### 4.1.5 安全规范

- **API Key / 密钥**：仅通过环境变量注入，禁止硬编码，禁止提交到 Git
- **SQL 注入**：全部通过 SQLAlchemy 参数化查询，禁止 f-string 拼接 SQL
- **路径穿越**：文件操作必须校验路径在允许目录内（`resolve().is_relative_to()`）
- **code_exec 安全**：危险操作过滤列表必须维护，新增危险模式及时补充
- **日志脱敏**：API Key、用户输入中的潜在隐私数据在日志中替换为 `***`

### 4.3 提交规范（Conventional Commits）

#### 4.3.1 提交格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

#### 4.3.2 Type 类型

| type | 说明 | 示例 |
|---|---|---|
| `feat` | 新功能 | `feat(agent): add planner agent task decomposition` |
| `fix` | Bug 修复 | `fix(mcp): fix session leak on executor exception` |
| `docs` | 文档变更 | `docs(readme): add quick start section` |
| `style` | 代码格式（不影响逻辑） | `style: run ruff format` |
| `refactor` | 重构（不新增功能不修bug） | `refactor(eval): extract scorer into separate module` |
| `perf` | 性能优化 | `perf(db): batch insert agent messages` |
| `test` | 测试相关 | `test(agent): add state graph routing tests` |
| `chore` | 构建/工具/依赖 | `chore: add pytest-cov to requirements` |
| `ci` | CI 配置 | `ci: add python 3.12 to test matrix` |

#### 4.3.3 规则

- **subject**：不超过 50 字符，祈使句（"add" 而非 "added"），结尾不加句号
- **scope**：可选，标明影响模块（agent/mcp/eval/api/db 等）
- **body**：可选，详细说明变更原因与内容，每行不超过 72 字符
- **footer**：可选，关联 issue 或标注破坏性变更（`BREAKING CHANGE:`）
- **原子提交**：一个提交只做一件事，禁止混合多个不相关变更
- **提交频率**：每个任务完成后至少 1 次提交，大任务可拆分为多次提交

#### 4.3.4 分支策略

- `main`：受保护分支，仅通过 PR 合并，必须通过 CI
- `feat/<模块>-<功能>`：功能分支，如 `feat/agent-state-graph`
- `fix/<问题>`：修复分支，如 `fix/mcp-session-leak`
- 开发完成后提 PR 到 main，自审后合并（1人项目自审，但需确保 CI 通过）

### 4.4 注释规范

#### 4.4.1 文档字符串（Docstring）

所有公共模块、类、函数必须有 Google 风格 Docstring：

```python
def execute_tool(self, tool_name: str, arguments: dict[str, Any]) -> str:
    """执行指定 MCP 工具并返回结果。

    Args:
        tool_name: 工具名称，必须已在注册中心注册
        arguments: 工具参数，需符合工具的 JSON Schema

    Returns:
        工具执行结果的文本内容

    Raises:
        ToolNotFoundError: tool_name 未注册时抛出
        ValidationError: 参数校验失败时抛出
        ToolTimeoutError: 工具执行超时时抛出

    Note:
        调用前会自动执行 JSON Schema 参数校验（T-04 要求 100% 覆盖）。
    """
```

**要求**：
- 公共 API（非下划线开头）必须有完整 Docstring（Args/Returns/Raises）
- 私有函数可简化，但复杂逻辑必须说明
- 模块顶部 Docstring 说明模块职责与主要导出

#### 4.4.2 行内注释

- **注释为什么**，不注释做什么（代码本身应能说明做什么）
- 复杂算法、业务规则、临时方案必须注释
- TODO/FIXME 必须标注责任人与日期：`# TODO(zhangsan, 2026-10-15): 优化为批量查询`
- 禁止无意义注释（如 `i += 1  # i 加 1`）

#### 4.4.3 架构决策注释

关键架构决策处必须注释引用架构文档章节：

```python
# P1-2 修正：Session 为任务级，非全局单例，避免多任务串话
# 详见架构文档 §3.2.3
async with self._create_session() as session:
    ...
```

涉及评审修正项（P0-1/P1-1~P1-10/P2-1~P2-10）的代码必须标注对应编号。

#### 4.4.4 禁止事项

- 禁止注释掉的代码（用 Git 历史管理）
- 禁止 `print()` 调试输出（MCP stdio 约束 + 统一 logging）
- 禁止在注释中包含敏感信息（API Key、内部 URL）
