## 二、P0 级问题逐条验证

### BUG-001【P0】Celery 默认被错误启用，任务执行链路完全中断

**问题摘要**：`celery_app.py` 默认 `CELERY_ENABLED=True`，且 `config.py` 未定义 `celery_enabled` 字段，导致 Celery 被错误启用但无 Worker 消费，任务永久 pending。

**验证步骤**：

1. 确认配置文件默认值：打开 `config.yaml`，确认 `celery_enabled: false`（或该字段不存在时代码默认 false）
2. 确认代码默认值：打开 `app/workers/celery_app.py`，确认 `CELERY_ENABLED = getattr(_config, "celery_enabled", False)` 默认值为 `False`
3. 确认 `app/config.py` 的 `AppConfig` 类中存在 `celery_enabled: bool = False` 字段
4. 启动服务：`uvicorn app.main:app --port 8000`
5. 创建任务：
   ```
   curl -X POST http://localhost:8000/api/v1/tasks -H "Content-Type: application/json" -d "{\"input\":\"回归测试任务\",\"scenario\":\"orchestration\"}"
   ```
   记录返回的 `task_id`
6. 观察服务日志，确认输出 `task_submitted_sync`（同步降级），**不应**出现 `task_submitted_celery`
7. 等待 5 秒后查询任务状态：
   ```
   curl http://localhost:8000/api/v1/tasks/{task_id}
   ```

**预期结果**：
- 配置和代码默认值均为 `False`
- 服务日志输出 `task_submitted_sync`，无 `task_submitted_celery`
- 任务状态为 `completed`（而非 `pending`）
- `started_at` 和 `completed_at` 均有值
