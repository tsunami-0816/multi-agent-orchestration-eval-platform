## 二、新发现问题（清单未覆盖）

### NEW-001【P0 阻塞】executions API 字段与模型完全不匹配，调用必抛异常

- **文件**：`app/api/v1/tasks.py:156-167`
- **问题**：`get_task_executions` 中访问 `e.status`、`e.node`、`e.input`、`e.output`、`e.error_message`、`e.started_at`、`e.completed_at`，但 `TaskExecution` 模型（`models/task.py:92-119`）实际字段为 `agent_role`、`node_name`、`input_data`、`output_data`、`round_number`、`created_at`。
- **影响**：调用 `GET /api/v1/tasks/{task_id}/executions` 必然抛出 `AttributeError`，节点执行记录查询接口完全不可用。
- **复现**：任意任务调用该接口 → 500 错误。

### NEW-002【P1 严重】任务 started_at 和 duration_seconds 永远为 NULL

- **文件**：`app/workers/tasks/orchestration.py:100-125`
- **问题**：`_update_task_status` 中，状态变为 `running` 时未设置 `task.started_at`；终态（completed/failed/cancelled）时未计算 `task.duration_seconds`。仅设置了 `status`、`result`、`error_message`、`completed_at`。
- **影响**：数据一致性检查点 DC-1.4（时间字段完整）和 DC-1.5（耗时计算正确）永远不达标；前端无法显示开始时间和耗时。

### NEW-003【P1 严重】task_repo.update_status() 状态判断用大写，与系统小写不一致

- **文件**：`app/repositories/task_repo.py:98-103`
- **问题**：`update_status` 中判断 `status == "RUNNING"`、`status in ("COMPLETED", "FAILED", "CANCELLED")` 用大写，但系统中所有状态写入均为小写（见 BUG-002）。若有代码调用此方法，`started_at` 和 `duration_seconds` 不会被设置。
- **影响**：该方法当前虽未被 `_update_task_status` 调用（后者直接操作 ORM 对象），但作为公共 Repository 方法存在隐患，任何调用方都会踩坑。

### NEW-004【P1 严重】报告记录应创建两条（html/json），当前只尝试创建一条且字段全错

- **文件**：`app/report/generator.py:269-301`
- **问题**：`_save_report_record` 只尝试创建一条 `EvalReport`，但模型 `uq_report_run_type` 唯一约束（`models/eval.py:165`）要求按 `report_type` 区分，应创建 `report_type="html"` 和 `report_type="json"` 两条记录，各对应一个 `file_path` 和 `file_size_bytes`。
- **影响**：即使修复了字段名不匹配（BUG-010），也只能保存一种格式的报告记录，另一种缺失；且 `file_size_bytes` 为 `nullable=False`，当前未传入会报错。

### NEW-005【P2 一般】agent_messages 持久化缺少关键字段，sequence 语义错误

- **文件**：`app/agent/orchestrator.py:188-196`
- **问题**：`_persist_messages` 创建 `AgentMessage` 时仅设置 `task_id/role/content/node/sequence`，缺少 `agent_role`（发送方 Agent 角色）、`message_type`（text/tool_call/tool_result）、`round_number`（协作轮次）。且 `sequence=i` 是全局消息序号，而模型注释（`models/task.py:145`）定义为"轮次内消息序号"。
- **影响**：轨迹回放时无法按轮次分组、无法区分消息类型、无法识别发送方 Agent 角色；与架构 §3.9.1 要求的"按轮次分组展示"不符。
