## 三、引入新问题（修改影响范围内）

> 以下问题是在验证 REG-001 修复代码时，于修改影响的评测执行链路中新发现的问题。

### REG2-001【P2 一般】评测用例完全失败时不递增 `completed_cases`，运行可能永久停留 running

- **发现位置**：`app/workers/tasks/eval_case.py:30-48`（`_run_eval_case_sync` 外层 except）、`eval_case.py:72-73`（case/run 不存在提前返回）
- **问题描述**：REG-001 修复覆盖了 Agent 执行异常但仍继续评分的场景（`task_error` 非空 → `failed=True` → 递增），但以下三种"用例完全失败"场景不会调用 `increment_completed_cases`：
  1. **DB 连接失败**：`_execute_eval_case` 第 65 行 `async with async_session_factory() as db:` 抛异常 → 冒泡到 `_run_eval_case_sync` 外层 except → 返回 failed 字典，不递增
  2. **case/run 不存在**：`_execute_eval_case` 第 72-73 行提前 `return {"status": "failed"}`，不递增
  3. **评分保存失败**：第 157-178 行评分写入或递增本身抛异常 → 冒泡到外层 except，不递增
- **影响**：当上述场景发生时，`completed_cases` 不递增，`check_completion` 中 `completed_cases < total_cases` 永远成立，评测运行状态永久停留在 `running`，不会生成报告。用户看到"永远在执行中"。
- **与 REG-001 的关系**：REG-001 修复了 Agent 执行异常的递增问题，但未覆盖用例完全失败的边界场景。属于 REG-001 修复的延伸盲区，非修复引入的回归。
- **修复建议**：在 `_run_eval_case_sync` 外层 except 中增加兜底递增逻辑——捕获异常后调用 `increment_completed_cases(run_id, passed=False, failed=True)`，确保无论何种失败场景都能推进运行进度。
