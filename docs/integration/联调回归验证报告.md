## 三、引入新问题（修改影响范围内）

> 以下问题是在验证修复代码时，于修改影响的关联功能链路中新发现的问题。

### REG-001【P1 严重】`failed_cases` 字段已添加但从未被递增，BUG-011 修复不完整

- **发现位置**：`app/repositories/eval_repo.py:152-185` `increment_completed_cases()`
- **问题描述**：BUG-011 修复在 `EvalRun` 模型中添加了 `failed_cases` 字段（`models/eval.py:85-87`），但 `increment_completed_cases` 方法仅递增 `completed_cases` 和条件递增 `passed_cases`，**没有任何代码递增 `failed_cases`**。
- **调用链确认**：`eval_case.py:174` 调用 `increment_completed_cases(run_id, passed=passed)`，仅传 `passed` 参数；方法签名无 `failed` 参数。
- **影响**：
  1. 当评测用例 Agent 执行失败但仍生成评分时（`eval_case.py:127-141` 异常分支），`completed_cases` 递增但 `failed_cases` 仍为 0
  2. 当用例任务完全失败未生成评分时（`_run_eval_case_sync` 异常分支），`completed_cases` 不递增，`failed_cases` 也不递增，运行将永远停留在 running 状态
  3. 前端报告页"通过/失败"卡片中失败数永远显示 0，与实际失败用例数不符
- **修复建议**：`increment_completed_cases` 增加 `failed: bool = False` 参数，当 `failed=True` 时递增 `failed_cases`；`eval_case.py` 在 Agent 执行异常分支传 `failed=True`。

### REG-002【P2 一般】`TaskMessageResponse` 缺少 `agent_role/message_type/round_number` 字段，trace 接口不返回已存储数据

- **发现位置**：`app/schemas/task.py:58-69`
- **问题描述**：BUG-004/NEW-005 修复已在 `agent_messages` 表中存储 `agent_role`、`message_type`、`round_number` 三个字段，但 `TaskMessageResponse` Schema 仅定义了 `id/task_id/role/content/node/sequence/created_at`，trace 接口返回数据中不包含这三个字段。
- **影响**：前端轨迹查看页面无法按轮次分组展示、无法区分消息类型（text/tool_call/tool_result）、无法识别发送方 Agent 角色，与架构 §3.9.1"按轮次分组展示"要求不符。数据已持久化但未暴露。
- **修复建议**：在 `TaskMessageResponse` 中添加 `agent_role: Optional[str]`、`message_type: str`、`round_number: int` 三个字段。
